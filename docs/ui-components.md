# UIコンポーネント

操作UIの共通部品は `components/ui/controls.ts` から使います。グラフの状態や翻訳は呼び出し側で扱い、共通部品は機能に依存させません。

| 部品                              | 用途                                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `Button` / `IconButton`           | 通常の操作、アイコンだけの操作                                                                                   |
| `ChoiceButton`                    | 配置や書き出し用途などの選択・実行ボタン。`layout="tile"` でアイコン・名前・補足を縦に並べる                     |
| `Segment`                         | 相互に排他的な選択。選択状態、チェックマーク、矢印キー、Home/End、1つのTab停止点を管理する                       |
| `OptionToggle`                    | 真偽の設定。行全体が操作対象で、右端のチェックボックスに状態を示す                                               |
| `Select` / `TextInput` / `Slider` | ネイティブ入力、選択、数値の調整                                                                                 |
| `ControlGroup`                    | パネル内の見出しと項目間の余白。連続するチェック行は `spacing="tight"`                                           |
| `ControlRow`                      | 短い見出しを左、操作を右に並べる。長い見出しは `layout="stacked"`。単一の入力には `htmlFor` と入力の `id` を結ぶ |
| `ActionRow`                       | メニューや設定内の行操作。削除は `tone="danger"`、確認待ちは `active`、補足は `trailing`                         |
| `PanelActions`                    | パネル下部の操作を等幅で並べる。子の `Button` は `wrap` を指定する                                               |

## 見た目の変更場所

- 色・面・文字色は `app/globals.css` の意味別トークンを使う。明暗テーマごとの色を各パネルに書かない。
- 装飾の区切りには `--line`、入力や操作の境界には `--control-border`、選択を示す境界には `--control-accent` を使う。フォーカスは `focusRing` または `ge-focus` で `--focus` の輪郭を示す。薄い影だけをフォーカスの手掛かりにしない。
- 操作のフォーカス、面、アイコンの線幅は `components/ui/control-styles.ts` で管理する。Lucideの線幅は1.75、サイズは使用場所に合わせる。ブランド画像は固有の形を維持する。
- 押している間は共通の `pressFeedback` で現在の面に薄く色を重ねる。位置や大きさを動かさず、選択状態を維持する。無効な操作には適用しない。
- ボタンのサイズ・選択状態・無効状態は共通部品のプロパティで指定する。`className` は配置に使い、各パネルで枠・背景・線幅を上書きしない。
- 上部ツールバーの各パネル内は折り返さない。幅や文字サイズに応じてラベルとキーヒントを非表示にし、アイコン・全文の操作名・tooltipを残す。三点リーダーで文字を切らない。モバイルではパネル同士の改行を許容する。パネル内の長い説明や操作は `Button wrap`、長い選択肢は `Segment wrap` を使い、操作領域は44px以上を保つ。
- パネルの外枠、閉じる操作、フォーカス移動、スクロールは既存の `EditorPanelShell` で管理する。パネルごとに作り直さない。
- モーダルとモバイルのパネルでは、Tab・Shift+Tabをパネル内で明示的に循環させる。`summary` を含む有効で可視のTab停止点を対象とし、hidden・inert・disabled状態やroving tabindexの非選択項目を除外する。Ctrl・Alt・Meta付きの操作、IME変換中、処理済みのイベントは奪わない。
- パネルの外を押すと閉じる。パネル内の操作は維持し、表示ボタンによる開閉や別パネルへの切り替えはボタン側で管理する。閉じるボタンとEscも共通で使える。
- tooltipは `data-tooltip` と `data-tooltip-side` で指定し、`TooltipLayer` が画面内に配置する。上下の余裕に応じて表示側を切り替え、左右は画面端から8px以上空ける。パネルごとに表示処理を追加しない。
- tooltip自体にポインターを移して読み続けられるようにする。利用条件やエラーなど、操作に必要な情報はtooltipだけに置かず、画面内にも表示して関連付ける。

設定・PNG・書き出し・配置・読み込み・アプリメニューに共通部品を適用しています。ツールバー、選択パネル、サンプル一覧も同じ操作部品を使います。ガイドの本文用部品（`ContentSection`、`Card`、`Callout`など）も `components/ui` に置き、同じ色トークンを使います。

## アクセシビリティの設計根拠

[デジタル庁のアクセシビリティ指針](https://design.digital.go.jp/dads/guidance/accessibility/)、[カラーの要件](https://design.digital.go.jp/dads/foundations/color/accessibility/)、[入力のラベルとサポートテキスト](https://design.digital.go.jp/dads/components/input-text/usage/)を基準に、通常の文字は4.5:1以上、操作の境界とフォーカスは3:1以上を確保します。装飾の区切りと無効な操作は同じ基準の検証対象には含めません。

[Apple HIGのレイアウト](https://developer.apple.com/design/human-interface-guidelines/layout)と[ボタン](https://developer.apple.com/design/human-interface-guidelines/buttons)も参照し、関連する操作をまとめ、表示ラベルと操作対象を結び付け、狭い画面でも内容を確認できる構造を保ちます。ネイティブアプリ固有の素材や外観をそのまま移すのではなく、このウェブアプリに適用できる操作原則を採用しています。

- 入力には表示ラベルを付け、説明・エラーを `aria-describedby` で関連付ける。適用を妨げるエラーは `aria-invalid` と文字の説明で示し、適用可能な警告と区別する。省略した診断は展開してすべて確認できるようにする。
- 入力例はplaceholderにせず、入力中も参照できる開閉欄に置く。例の入力ボタンは空欄のときだけ表示し、入力済みのデータを置き換えない。全形式の例を0始まり・1始まりの両方で実際のパーサーに通す。
- 入力中に変わる診断本文は静的に表示し、`role="alert"` や `aria-live` で入力を中断しない。読み込み状態と、明示的なコピー操作の結果は別のstatus領域で伝える。コピー失敗時は手動コピー・ファイル保存への説明を残す。
- 数値欄は入力途中の空文字を保持し、blurまたはEnterで確定する。PNGの幅・高さにはpx単位と範囲を示し、IME変換中のEnterを確定操作に使わない。
- スライダーの表示ラベルは入力に関連付ける。値とプリセットの読み上げ名には単位と対象を含める。チェック項目の補足は名前から分けて説明として関連付ける。
- IMEの変換中、Altを含む操作、処理済みのキーイベントを編集ショートカットで奪わない。読み込み欄の適用操作も同じ原則に従う。
- 通常のUI文字サイズは `rem` を基準とし、ショートカット一覧はラベルの折り返しに応じて行を伸ばす。
- モバイルの編集モードには短い常時ラベルを添える。頂点モードではネイティブボタンのEnter・Spaceでも頂点を追加でき、続けて操作してもフォーカスを維持する。辺の頂点ボタンも同じ標準操作で接続できるようにする。
- ツールバーは文字の拡大に応じて表示項目を調整し、下部ではグループごとの折り返しを許容する。上部・下部の操作領域を実測し、`editor-chrome-bounds` と共有する。ヒント・通知・追加操作・頂点配置・表示領域に戻す操作に反映する。頂点が収まる場所がない場合は追加せず、画面を広げるなどの対処を表示する。
- クリアの確認は読む時間を制限せず、キャンセルを用意する。確認の初期フォーカスはキャンセルに置き、連続したEnterで意図せず確定しないようにする。

`tests/verification/design-contrast.ts` は明暗テーマの実際の色トークンを検証します。半透明の重なりや実際のフォーカス表示は、この検証だけでは確認できません。Safariの固定ローカル検証は `design-guidelines-results.json` に入力・確認・出力の操作結果、`responsive-text-results.json` に狭い編集領域と拡大文字の描画寸法を記録します。実際のビューポートと編集領域の寸法、確認内容、スクリーンショットを区別して保存します。これらは専門家による実装・操作レビューであり、スクリーンリーダーの実機試験や初回利用者の観察、アプリ全体の適合認証を意味しません。

文字拡大時の自動辺経路は、描画中の頂点幅と高さを一時的な測定値としてTypeScript・Worker・Rust/Wasmへ渡します。衝突判定、候補評価、自己ループ、ドラッグ中の現在位置と移動前の障害物に同じ寸法を使い、高さだけの変更でもキャッシュを無効化します。保存するグラフには測定値を含めません。32・48・72・96pxと高さが混在する境界テストを行い、Safariでは16→24→16pxの文字変更に伴う48→72→48pxの描画と実際の辺の余白を検証します。頂点同士の自動配置間隔は別の計算で、今回の辺経路の検証対象には含めません。

## 確認

`node scripts/toolchain.mjs run check` に加え、in-app browserで320px幅の長い翻訳、短い画面のスクロール、明暗テーマ、選択肢の矢印操作、ラベルを押したときの入力フォーカス、閉じて開き直したときのフォーカスを確認します。レイアウトの変更はグラフのデータ処理や保存処理から分けて扱います。
