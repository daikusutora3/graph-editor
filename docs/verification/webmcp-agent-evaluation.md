# WebMCP: Codex による探索的な操作評価

2026-10-29 に、一括編集を追加したローカル版を、自然言語の指示から Codex が使えるか確認しました。各ケースは基本的に1回の試行であり、成功率の推定ではありません。利用した Codex サブエージェントは親の設定を継承しましたが、正確なモデル名は記録できていません。ブラウザーは隔離した Chromium 156.0.8078.4 です。

## 方法

各試行で新しいブラウザーと合成グラフを用意しました。評価役には利用者の依頼と、ページの WebMCP ツールを発見・実行する手段を知らせ、期待されるツール名や引数、fixture の実装、採点方法は知らせませんでした。ただし起動引数として `basic` または `ambiguous` という fixture 名は見えていました。操作は Playwright の `page.webmcp.tools()` と `page.webmcp.callTool()` を介してブラウザーのネイティブ WebMCP に届きます。これは自然言語からツールと引数を選ぶ評価です。モデルを介さず決め打ちで呼ぶブラウザーテストとは区別します。

`tests/browser/webmcp-eval-bridge.mjs` は `127.0.0.1:3323/en` だけを開き、合成グラフ、操作履歴、最終グラフを一時ディレクトリの JSONL に保存します。`tests/browser/webmcp-eval-grade.mjs` は初期状態・最終状態と変更回数を比較します。曖昧な指示については、評価役の最終応答で利用者に説明したことも確認しました。fixture は頂点 1〜6 の重み付き無向グラフと、そのうち頂点名と辺を重複させたバリエーションです。

## 結果

- 頂点 1・2・3 を赤にする: 一括編集1回で成功。対象外のデータを保持。
- 辺 1–2 と 3–4 を青にする: 一括編集1回で成功。対象外のデータを保持。
- 頂点 6 の名前と2本の辺の重みを異なる値に変更: 一括編集1回で成功。
- 全頂点を赤にする: 全頂点指定で一括編集1回。辺と設定を保持。
- 頂点 2 と 4 を削除: 一括削除1回で成功。接続する4辺を削除し、残りを保持。
- 同名の頂点 1 と頂点 3 を赤にする: 対象を特定できないと説明し、全体を変更しなかった。
- 平行辺のある 3–4 の辺を1本だけ赤にする: 2本のどちらかを確認する必要があると説明し、変更しなかった。
- 頂点 1・2・3 を赤にして、その変更を一度で取り消す: 一括編集後に Undo を1回実行し、初期状態に戻した。

最初の色変更の試行では、Codex が編集前に `get_graph` で全 JSON を取得しました。説明を修正した後に同じ依頼を別エージェントへ再試行しても、全 JSON と概要の両方を取得しました。一方、全頂点の色変更と Undo の試行では概要を使用しました。この少数の試行から、説明変更が取得量を減らしたとは判断できません。大きなグラフでの出力量とツール選択は追加評価が必要です。

評価の初回に、対話用プロセスを TTY なしで起動して標準入力が閉じたケースと、開発サーバー停止による接続失敗がありました。いずれも操作前の環境上の失敗で、環境を修正してから試行しています。これらをツール選択の成功に数えていません。

## 大規模グラフでの再評価

大きなグラフでの対象検索と出力制限を追加後、同日に新しい Codex サブエージェントによる6シナリオを試しました。各シナリオは1試行です。最初の5シナリオを実施後、選択中の多数の要素を扱う機能を追加し、6つ目を実施しました。評価役にはツール一覧のほか、起動時の fixture 名 `large-1`、`large-2` または `large-3` が見えています。`large-2` には同名の頂点と平行辺を、`large-3` には画面操作による範囲選択を用意しました。各試行は別の Chromium 156.0.8078.4 で実行しています。

- 1,000頂点・4,000辺から頂点 998・999・1000 を赤に変更: 一括変更1回で成功。ツール応答合計 2,416 bytes。
- 頂点 1000 の名前と辺 999–1000 の重み・色を同時に変更: 一括変更1回で成功。ツール応答合計 2,016 bytes。
- 頂点 998・999 と接続辺を削除: 一括削除1回で成功。ツール応答合計 1,879 bytes。
- 同名の頂点 998 と頂点 999 を変更: 同名の候補を確認し、どちらも変更せず説明。ツール応答合計 995 bytes。
- 平行辺のある 999–1000 の辺を1本だけ変更: 2本の候補を確認し、変更せず説明。ツール応答合計 812 bytes。
- 画面で選択中の頂点をすべて赤に変更: 実際の Shift ドラッグで選択された80頂点のみを一括変更。選択中の辺を含め、他の要素は維持。ツール応答合計 1,704 bytes。

いずれも Codex の操作中にグラフ全文の取得は成功していません。比較のための全文はブラウザーブリッジが評価終了後に明示的に取得し、評価役には渡さず、初期状態との差分を別途採点しました。2つ目の試行では、その全文応答は約375 KBでした。上記の応答量は評価役が呼んだツールの結果だけの UTF-8 サイズであり、ツール一覧・fixture の準備・採点用の全文は含みません。これらの試行は用途ごとの例であり、全エージェント・全グラフでの成功率を示すものではありません。

## 操作範囲と保存状態の再評価

同日に、要素の一括追加・移動、辺の反転、接続辺の検索と変更応答の保存状態を追加した版で、別の Codex サブエージェントを使って5シナリオを各1回実施しました。期待するツール名や引数は知らせず、各試行は独立した Chromium 156.0.8078.4 のページで開始しました。起動引数の fixture 名は評価役に見えています。有向グラフの fixture は `directed-1`、保存状態の fixture は内容を示さない `case-b` としました。

- 頂点 4 の接続先と重みを聞く: 接続辺を1回検索し、頂点 3・5 と重み 3・4 を回答。グラフは無変更。
- 頂点 7・8 と重み付きの辺 6–7・7–8 を追加: 一括追加1回で成功。既存要素を保ち、新しい頂点の重なりもなし。
- 頂点 1・3 をそれぞれ指定した座標へ移動: 一括変更1回で成功し、他要素を保持。
- 有向辺 1→2・3→4 を逆向きにする: 一括反転1回で成功し、他要素を保持。

## 条件指定と相対配置の評価

同日に、条件指定による色変更と相対配置を追加した版を、独立した Codex サブエージェントで評価しました。各依頼では期待するツール名・引数、fixture の内容、採点方法を知らせず、ブラウザーのツール一覧から操作を選んでもらいました。起動引数の fixture 名は見えています。各ケースは1試行で、Chromium 156.0.8078.4 の独立したページを使いました。

- 1,000頂点・4,000辺のグラフで「青い頂点をすべて赤く」: 143頂点を変更。
- 同じグラフで「重みが10以上の辺をすべて青く」: 1,876辺を変更。
- 同じグラフで「頂点4に隣接する頂点をすべて赤く」: 8頂点を変更。
- 「頂点1と3を右へ50移動」: それぞれの x 座標だけを 50 増やした。
- 「頂点1・3・5を頂点1と同じ高さに揃える」: 指定頂点の y 座標を頂点1に合わせた。
- 数値として比較できない重みを含むグラフで「重みが10以上の辺をすべて青く」: 数値の2辺を変更し、比較できず除外した1辺を利用者に説明した。

各試行で変更は1回、最終グラフの対象外要素は不変でした。大規模グラフの3ケースでは、エージェントによるグラフ全文の取得はなく、ツール結果の合計はそれぞれ 1,437、1,438、1,435 bytes でした。ツール一覧、fixture の準備、評価終了後に採点用として取得した全文は含みません。

独立レビューで大きな整数を通常の JavaScript 数値に変換すると比較を誤る問題が見つかり、十進表記を丸めず比較するよう修正しました。修正後、重み10以上の大規模ケースを別エージェントで再試行して同じ結果を確認しました。さらに「重みが9007199254740993以上の辺をすべて青く」という依頼を別の fixture で試し、Codex が境界を文字列で指定して該当する1辺だけを変更し、十進数でない重み1件を除外したと説明しました。このケースも変更は1回で、対象外は保持されました。比較不能な重みを含む前述の小規模ケースは修正前の結果です。

条件に合う要素を画面で選択し、他の編集につなぐ機能を追加した後、同じ大規模グラフを使って次の2ケースを別エージェントで各1回試しました。どちらもグラフ全文を取得せず、選択と1回のグラフ編集を行い、対象外の要素を維持しました。

- 「青い頂点をすべて右へ50移動」: 143頂点を条件選択して移動し、選択状態が残ったことも説明。ツール応答合計 1,775 bytes。
- 「重みが10以上の辺をすべて削除」: 1,876辺を条件選択して削除。ツール応答合計 1,736 bytes。

## 条件指定の直接編集: 改善前後の比較

同日、既存の画面選択を変更せずに条件指定で編集できるか、改善前後の両版で同じ fixture と同じ日本語の依頼を試しました。グラフは1,000頂点・4,000辺で、編集対象ではない頂点200を実際の画面操作で事前選択しています。各版・各依頼は別の Codex サブエージェントによる1試行で、Chromium 156.0.8078.4 を使用しました。ツールの実装と採点内容は評価役に知らせていません。

- 「青い頂点をすべて右へ50移動してください。他の要素は変えないでください。」改善前は143頂点の移動に成功しましたが、事前選択は条件に合う143頂点に置き換わりました。改善後は143頂点を1回のグラフ編集で移動し、事前選択も保持しました。ツール結果の合計は改善前 2,345 bytes、改善後 1,475 bytes です。
- 「重みが10以上の辺をすべて削除してください。他の要素は変えないでください。」改善前の評価役は既存選択の保持を優先して全文 JSON を取得し、ID 指定で計70辺を2回に分けて削除した時点で評価者が時間の都合により打ち切りました。対象1,876辺のうち1,806辺が残っており、最終的に完了できなかったとは判断できません。改善後は条件を直接指定し、事前選択を保持したまま1回のグラフ編集で1,876辺を削除しました。結果の合計は改善前の打ち切り時点で 379,439 bytes、改善後 1,515 bytes です。改善前には不完全な JSON 入力行が1件あり、ツールは実行されませんでした。

改善後の2試行では、どちらもグラフ全文を取得せず、初期グラフと最終グラフの全要素を照合して対象外のデータが変わっていないことを確認しました。選択状態も別途照合しています。試行時のツール一覧の JSON は同じ測り方で改善前 31,056文字、改善後 28,133文字でした。その後、比較可能な重みの上限をスキーマの説明に追記しています。文字数はトークン数ではなく、応答 bytes はツール一覧・準備・評価終了後の採点用全文を含みません。少数の試行であり、成功率や速度を統計的に比較した結果ではありません。

単独更新ツールの統合後、同じ fixture で「頂点1を赤く」「辺1–2の重みを12に」と依頼し、それぞれ一括変更ツールで1件だけを変更できました。また「重みが10以上の辺の重みをすべて2に」という依頼では、条件を直接指定して1,876辺を一度に変更しました。各試行は別エージェントによる1回で、最終グラフ全体と事前選択を別途照合しています。
